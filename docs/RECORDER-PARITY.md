# Recorder parity (headless)

Every user-facing recording, editing and export capability of Recorder (the reference app,
`~/projects/recorder`: `docs/SPEC.md` with its `AC-*` acceptance criteria, `docs/MCP.md`,
`docs/AUDIO-LAYERS.md`) against Splice's headless MCP surface. One row per capability.

- **Splice MCP call**: the tool or `edit.apply` command and the arguments that do it.
- **Evidence**: a test, named as `cargo t` prints it (`crate::module::test`; run it with
  `cargo t -p <crate> <test>`), an eval task in `evals/tasks/` (`eval:<id>`, 3/3 in both arms at
  63fe58a, PLAN.md T46.6), or `live:` for a capture verified by hand on the Mac mini.
- **Status**: `verified` (evidence above proves it), `UI-only` (a control for a human at a
  screen; not applicable headless, the reason says why), or `GAP` (missing, or present without
  proof; the note says what it would extend).

`splice_mcp::tests::recorder_parity_evidence_exists` parses this table and fails when a named
test or eval no longer exists, so the matrix cannot rot. Recorder-only UI chrome (onboarding
windows, timeline gestures, inspector tabs, keyboard maps) is listed once per area, not per
control: an agent sends the command the control would.
